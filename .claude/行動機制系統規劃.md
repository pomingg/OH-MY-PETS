## 📋 8 個子系統概覽與實現建議

### 子系統 1️⃣：自動告警系統

#### 系統目標
- 當指標進入紅/黃區時自動生成告警
- 告警內容包括：異常詳情、建議行動、優先級

#### 實現方案

**✅ 必須實現的部分**:
```
1. 告警規則引擎
   ├─ 監控所有關鍵指標 (P0 級別)
   ├─ 比較實時值 vs 預警門檻
   ├─ 根據「決策目標與指標分層」文檔生成告警規則
   └─ 例: IF 稼動率 < 75% AND 未在 1 小時內改善 → 告警

2. 告警記錄資料庫
   ├─ 存儲異常歷史
   ├─ 紀錄: 異常ID、時間、指標、狀態(新/進行/已解決)
   └─ 支援查詢和統計

3. 告警優先級判斷
   ├─ P0: 立即處理 (現金流危機、生產停機等)
   ├─ P1: 今日內 (稼動率 60-75%, 達成率 -20% 等)
   └─ P2: 本周內 (趨勢異常、預警接近等)
```

**⚠️ 虛擬公司可簡化的部分**:
```
1. 實時推送系統
   ├─ 無需真實 Slack/Email 推送
   ├─ 改為: UI 頁面顯示「未讀告警」計數器
   ├─ 例: 【🔴 新異常 - 3 項待處理】
   └─ 點擊可展開告警清單

2. 推送通知內容
   ├─ 無需發送實際消息
   ├─ 改為: 在告警頁面顯示完整內容
   └─ 包含: 時間、優先級、詳情、建議行動
```

#### 虛擬實現架構
```
告警系統流程:
┌─────────────────────────────────────────────────────┐
│ 1. 指標變化 (實時監控)                              │
│    ↓                                                │
│ 2. 對比預警門檻值                                   │
│    ├─ IF 進入紅區 → P0 告警                        │
│    ├─ IF 進入黃區 → P1 告警                        │
│    └─ IF 趨勢異常 → P2 告警                        │
│    ↓                                                │
│ 3. 在「告警中心」頁面顯示                           │
│    ├─ 未讀告警計數 (紅點)                          │
│    ├─ 告警時間線                                   │
│    └─ 建議行動清單                                 │
│    ↓                                                │
│ 4. 記錄到「異常歷史」DB                             │
│    └─ 用於追蹤和統計                               │
└─────────────────────────────────────────────────────┘
```

### 子系統 2️⃣：責任人分配系統

#### 系統目標
- 異常出現時自動分配給對應負責人
- 記錄責任人的承諾和進度

#### 實現方案

**✅ 必須實現的部分**:
```
1. 責任人映射表
   ├─ Sales 異常 → 銷售總經理 (王經理)
   ├─ Production 異常 → 廠長 (李廠長)
   ├─ HR 異常 → HR總監 (陳總監)
   ├─ Finance 異常 → CFO (王CFO)
   └─ Overview 異常 → CEO (林CEO)

2. 分配規則引擎
   ├─ 根據異常所在頁面自動分配
   ├─ 支援「升級」(如主管無法在30分鐘內承諾)
   └─ 支援「跨部門分配」(如涉及多個部門)

3. 責任人確認流程
   ├─ 告警推送給責任人 → 對應 UI 頁面顯示
   ├─ 責任人可點擊「確認已收到」
   ├─ 記錄確認時間 (SLA: 5-15 分鐘內)
   └─ 逾期未確認時升級給主管
```

**⚠️ 虛擬公司可簡化的部分**:
```
1. 無需實際 Slack/Email 發送
   ├─ 改為: 在「我的待辦」頁面顯示分配的異常
   └─ 顯示: 【新分配給我: 2 項待確認】

2. 無需與日曆/考勤系統集成
   ├─ 改為: 假設所有責任人都在線
   └─ 簡化測試流程
```

#### 虛擬實現架構
```

│ 1. 告警產生 (自動告警系統 → 2️⃣)                    │
```

### 子系統 3️⃣：異常狀態追蹤系統

#### 系統目標
- 追蹤異常從「檢測」到「解決」的全生命週期
- 記錄進度和決議

#### 實現方案

**✅ 必須實現的部分**:
```
1. 異常狀態機
   ├─ 新建 (剛檢測出)
   ├─ 已確認 (責任人已讀)
   ├─ 進行中 (開始調查/處理)
   ├─ 待決策 (發現問題，等待決策)
   ├─ 已解決 (完成修復)
   └─ 已驗證 (確認效果)

2. 時間線紀錄
   ├─ 檢測時間
   ├─ 確認時間 (責任人確認已收到)
   ├─ 開始時間 (開始處理)
   ├─ 決策時間 (做出決策)
   ├─ 完成時間
   ├─ 驗證時間
   └─ 計算 SLA (從檢測到確認的時間)

3. 進度備註
   ├─ 責任人可輸入進度更新
   ├─ 每次更新記錄時間和操作人
   └─ 支援上傳附件 (如故障分析、會議記錄)

4. 相關聯系
   ├─ 異常可關聯到其他異常 (根本原因)
   ├─ 異常可關聯到決議或行動計畫
   └─ 便於後期分析根本原因
```

**⚠️ 虛擬公司可簡化的部分**:
```
1. 無需與工單系統集成
   └─ 改為: 直接在異常頁面記錄進度

2. 無需與日誌系統集成
   └─ 改為: 手工記錄決策過程

3. 無需驗證系統確認異常解決
   └─ 改為: 責任人確認後標記為「已解決」
```

### 子系統 4️⃣：會議整合系統

#### 系統目標
- 自動為日常戰情會生成「紅區清單」
- 會議中直接下鑽分析和決策

#### 實現方案

**✅ 必須實現的部分**:
```
1. 日度戰情會自動生成
   ├─ 時間: 每日 09:00
   ├─ 與會者: CEO + 各部門主管
   ├─ 會議模板自動從「告警系統」生成
   └─ 內容包括:
       ├─ 紅區異常清單 (P0 異常, < 5 項)
       ├─ 黃區監控項目 (P1 異常, < 10 項)
       └─ 關鍵進度指標 (銷售/生產/人力/財務達成率)

2. 會議決議記錄
   ├─ 會議中可輸入決議 (決策結果)
   ├─ 決議可綁定到對應異常
   ├─ 決議可指派執行者和截止時間
   └─ 會議記錄自動保存為備查

3. 會議內下鑽分析
   ├─ 點擊「C 廠稼動率 68%」可展開詳細分析
   ├─ 分析包括: 班次分布、機台分布、停機原因
   └─ 支援現場截圖或數據導出
```

**⚠️ 虛擬公司可簡化的部分**:
```
1. 無需與日曆系統集成
   ├─ 改為: 在儀表板上顯示「今日戰情會紅區清單」
   └─ 提醒: 09:00 會議即將開始

2. 無需與會議記錄軟體集成
   ├─ 改為: 在應用內記錄會議決議
   └─ 簡化記錄流程

3. 無需考勤驗證與會人員
   └─ 改為: 假設所有人都準時出席
```

### 子系統 6️⃣：優先級排序機制

#### 系統目標
- 自動判斷異常的優先級
- 確保關鍵異常優先處理

#### 實現方案

**✅ 必須實現的部分**:
```
1. 優先級評估矩陣
   
   維度 1: 業務影響
   ├─ 高 (影響營收/現金流/安全)
   ├─ 中 (影響進度 > 20%)
   └─ 低 (趨勢偏差 < 20%)
   
   維度 2: 緊急度
   ├─ 高 (< 1 小時內需決策)
   ├─ 中 (1-4 小時內需決策)
   └─ 低 (4+ 小時內需決策)
   
   結合得出優先級:
   ┌───────────────────┐
   │      高緊急度      │
   │  高影響 → P0      │
   │  中影響 → P1      │
   │  低影響 → P2      │
   │                   │
   │      低緊急度      │
   │  高影響 → P1      │
   │  中影響 → P2      │
   │  低影響 → P3      │
   └───────────────────┘

2. 自動分類規則
   
   P0 (立即處理, 0-30 分鐘):
   ├─ 生產停機 > 30 分鐘
   ├─ 現金流 < 30 天流動資金
   ├─ 重大品質事故 (良率 < 90%)
   └─ 關鍵客戶流失
   
   P1 (今日內, 1-4 小時):
   ├─ 稼動率 60-75% 範圍
   ├─ 達成率下降 15-20%
   ├─ 應收超期 30-45 天
   └─ 人力缺員 > 10%
   
   P2 (本周內, 4+ 小時):
   ├─ 趨勢異常 (環比下降 10-15%)
   ├─ 預警指標接近門檻
   └─ 非關鍵部門異常

3. 優先級顯示
   ├─ 用顏色 + 標籤標示 (🔴 P0 / 🟡 P1 / 🟢 P2)
   ├─ 異常清單按優先級排序
   └─ 在「待辦」頁面突出顯示 P0 異常
```

**⚠️ 虛擬公司可簡化的部分**:
```
1. 無需與風險評估系統集成
   └─ 改為: 手工定義優先級規則

2. 無需動態調整優先級
   └─ 改為: 根據預定義規則自動分類
```

#### 虛擬實現示例
```javascript
// 優先級判斷邏輯
function getPriority(anomaly) {
  const impact = getBusinessImpact(anomaly);
  const urgency = getUrgency(anomaly);
  
  if (impact === 'high' && urgency === 'high') return 'P0';
  if (impact === 'high' || urgency === 'high') return 'P1';
  return 'P2';
}

// 業務影響評估
function getBusinessImpact(anomaly) {
  if (anomaly.type === 'production' && anomaly.value < 0.6) {
    return 'high'; // 停機
  }
  if (anomaly.type === 'finance' && anomaly.metric === 'cash_flow') {
    return 'high'; // 現金流危機
  }
  if (anomaly.indicator_drop > 20) {
    return 'medium'; // 進度下降超 20%
  }
  return 'low';
}

// 時間緊急性
function getUrgency(anomaly) {
  const minutesSinceDetected = (now - anomaly.detected_at) / 60000;
  
  if (anomaly.priority === 'P0') return 'high'; // 0-30 分鐘
  if (minutesSinceDetected < 60) return 'high';
  if (minutesSinceDetected < 240) return 'medium'; // 4 小時
  return 'low';
}
```

### 子系統 8️⃣：異常反思與改善系統

```
   ├─ 預防措施 (如何避免重複)
```
